## 三、已修复的 Bug（`extract_article_fulltext.py`）

### Bug 1：`should_skip_div()` 子串误杀 → 大段正文丢失

**位置**：`should_skip_div()` 函数（约 L163-167）

**根因**：用 `kw in mulu_text` 做子串匹配。`「一　全部教史的綱要」` 包含 `「綱要」` 关键词，被误判为目录 div 而整节跳过。

**修复**：改为精确匹配集合 `{'目次', '綱要', '目錄', '目録', '科分'}`，只跳过标题恰好是这些词的 div。

**影响范围**：`佛教的教史教法和今後的建設` 丢失前两大节（一「全部教史的綱要」、二「全部教法的綱要」及 15 个子标题），正文损失约 46%。修复后恢复至 9 千字。

```python
# 修复前
def should_skip_div(mulu_text):
    for kw in ['目次', '綱要', '目錄', '目録', '科分']:
        if kw in mulu_text:  # ← 子串匹配！
            return True
    return False

# 修复后
def should_skip_div(mulu_text):
    skip_set = {'目次', '綱要', '目錄', '目録', '科分'}
    return mulu_text.strip() in skip_set  # 精确匹配
```

### Bug 2：`_render_list_items()` 丢弃无 `<p>` 包裹的列表项

**位置**：`_render_list_items()` 函数（约 L334-371）

**根因**：只处理 `<item><p>text</p></item>` 结构，对 `<item>text</item>`（文本直接在 item 中，无 `<p>` 包裹）直接丢弃。

**修复**：当 `item.find('p')` 为 None 时，用 `item.text` 提取直接文本，并处理内嵌的 `<note>` 元素。跳过嵌套的 `<list>` 子元素（由递归处理）。

**影响范围**：`論中國佛教史` 整列表（3 项）丢失，以及 `佛學講要`、`佛陀學綱`、`甚麼是佛學`、`諸法眾緣生唯識現` 等多篇文章的部分列表项。

### Bug 3：列表项在 MD 中无 `- ` 前缀

**位置**：同上函数

**根因**：`_render_list_items()` 输出的文本行没有 markdown 列表标记（`- `），导致验证脚本无法识别这些行是列表项。

**修复**：添加 `indent` 参数，为每项加 `- ` 前缀，嵌套列表用 4 空格缩进。

```python
# 关键变更
def _render_list_items(list_elem, notes_map, result_lines, indent=0):
    prefix = "    " * indent + "- "
    # ...
    result_lines.append(f"{prefix}{text}")
    # 递归嵌套列表时 indent + 1
    _render_list_items(child, notes_map, result_lines, indent + 1)
```

- 3 处正文标题错、纲目对（#1, #3, #5）
- 1 处纲目错、正文标题对（#6）

**不能盲从任何单一方**，需以纸质书为权威裁决。

## 六、验证脚本的已知局限

1. **MD 解析器**不处理 YAML frontmatter 之外的行内标记（如 `**粗体**`、行内 code）
2. **HTML 解析器**基于 Python `html.parser`，对 CBETA 特殊标签（如 `<cb:div>`）不做处理，只提取已渲染的 HTML 内容
3. **文本比较**依赖 `normalize_text()` 归一化，当前规则：去空格、统一括号、去顿号/逗号/句号、中文数字→阿拉伯数字。可能需要根据新数据调整
4. **note_content_missing** 检测依赖正则统计括号数量，可能漏检或被标点干扰
